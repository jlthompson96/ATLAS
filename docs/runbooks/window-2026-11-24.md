# Maintenance window, 2026-11-24 (after B10)

One window on the Pi for three jobs that each need the overlay off and root:

1. Install the nightly backup ([backup.md](backup.md), ADR 0002).
2. The Pi half of the WireGuard link ([wireguard.md](wireguard.md)), if `feat/wireguard-link` is merged by then.
3. The root-only items of [pi-verification.md](pi-verification.md), mostly through `deploy/provisioning/pi-verify.sh`.

**Expected length:** about 2 hours. You're needed at the start, after each of the two reboots (tmux and `sudo -v`), and at the console for the backup password and the drives.

**Who does what:** **Owner** steps need you: the console, the drives, or the sudo password. **Claude** steps run in the shared tmux session `claude` after you've typed `sudo -v` there. Claude asks before anything that destroys data (`mkfs`) or reloads the firewall.

**Optional, if `feat/ui-on-pi` is merged and time allows:** the HUD on the Pi ([ui-on-pi.md](ui-on-pi.md) steps 1–6) fits after step 13, with the overlay still off; step 5 there is the owner at the console for the approval PIN. Otherwise it gets a short window of its own.

**Not in this window:** FI-3 (20 power cuts) and PT-9 (restore onto the spare card) get sessions of their own. So do the egress checks against real hosts (Phase 4), segment rollover and purge (need time or data), and IPv6 (the LAN has none).

## Before the window (Mac only, any time)

- Decide whether to merge `feat/wireguard-link` (step 11 needs it) and `feat/window-plan` (this file, `pi-verify.sh`).
- Download `restic_0.18.0-1+b4_arm64.deb` and `wireguard-tools_1.0.20210914-3_arm64.deb` in the ARM64 VM and note their SHA-256 (backup.md step 1, wireguard.md step 1).

## If something goes wrong

- **A reboot doesn't come back:** console. The overlay argument's backup is `/boot/firmware/cmdline.txt.pre-overlay` (pi-bringup §11).
- **`provision-pi.sh` fails part-way:** it's idempotent; fix the cause and rerun. Nothing in this window changes the firewall except step 11.
- **A backup run fails:** `journalctl -u atlas-backup-mount -u atlas-backup`. The table in backup.md lists the messages. The window can finish without the backup; the timer simply stays off until it works.
- **pi-verify FAILs:** record them; each is a finding for known-issues.md, not a reason to stop the window, unless it says a sandbox or the firewall is open.
